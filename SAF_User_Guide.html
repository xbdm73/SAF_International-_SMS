MODE D'EMPLOI DU SYSTÈME SAF

Ce guide décrit l’utilisation opérationnelle des modules SAF International fournis : HOME, Safety Management System, Compliance Monitoring System, Appendices OMM et Safety / Security Report. Il est conçu pour être consulté directement depuis le système grâce aux liens « MODE D’EMPLOI » et au bouton d’aide ?.

1. Présentation générale du système SAF

Le système SAF regroupe quatre outils principaux : le Safety Management System (SMS), le Compliance Monitoring System (CMS), les Appendices OMM et le formulaire mobile Safety / Security Report. La page HOME sert de portail d’accès et de point de sauvegarde/restauration globale pour les profils autorisés.

ModuleFinalitéExemples de données
SMSIdentifier les dangers, évaluer les risques, suivre les occurrences, les changements, les barrières et la performance sécurité.Risk Register, MoC, ERP, SPI, Occurrence Log, Event Accounting, Bow-Tie, assurance, audits SMS.
CMSPlanifier et tracer la surveillance de conformité, les audits, les constatations, actions correctives et revues de management.Plan d’audit, KPI conformité, CAP, sous-traitants, auditeurs, formateurs, SRB, grille EASA, veille réglementaire.
Appendices OMMMaintenir les appendices organisationnels et opérationnels associés au manuel de gestion.Liste des appendices, installations, organigramme, personnel de management, leasing, aéronefs, promotion sécurité.
Safety / Security ReportPermettre un signalement rapide depuis téléphone, tablette ou PC.Évènement Safety, Security/Part-IS, anonymat, description, mesures immédiates, informations opérationnelles.
À retenir : Le guide décrit le comportement de la version SAF fournie. Il ne remplace pas l’OMM, l’OM-A, les procédures approuvées ni les obligations réglementaires applicables.

2. Accès, connexion et rôles utilisateurs

La page HOME adapte l’accès aux modules selon le rôle enregistré. Les rôles visibles dans le système sont Admin, Editor, Authority et Reader. Le rôle Reader est destiné à la consultation et le rôle Authority à une lecture étendue sans écriture.

RôleUtilisation attenduePrécaution
AdminAccès complet aux modules autorisés et fonctions de sauvegarde/restauration globale.Réserver les restaurations et modifications structurantes aux personnes habilitées.
EditorModification des données opérationnelles dans les modules accessibles.Vérifier la synchronisation avant fermeture.
AuthorityConsultation de l’ensemble des informations disponibles sans logique d’édition.Ne pas chercher à contourner les champs désactivés.
ReaderLecture seule ; l’accès peut être limité à certains modules publiés.Utiliser ce rôle pour consultation, briefing ou lecture contrôlée.

Procédure de connexion

  1. Ouvrir la page HOME.
  2. Sélectionner Connexion utilisateur.
  3. Saisir les identifiants autorisés.
  4. Contrôler le badge de rôle affiché après authentification.
  5. Ouvrir le module nécessaire depuis la carte correspondante.
  6. Sur un poste partagé, utiliser Déconnexion après utilisation.
Attention : Un bouton ou un champ non modifiable en lecture seule est un contrôle d’autorisation, pas nécessairement une panne.

3. Sauvegarde, synchronisation, exports et restauration

Le système combine des données persistées dans Supabase, des sauvegardes locales ou des exports explicites selon les modules. Il faut distinguer enregistrer une modification, exporter une preuve et restaurer une sauvegarde.

Séquence de travail recommandée

  1. Effectuer la modification dans le module concerné.
  2. Utiliser le bouton Save / Enregistrer lorsqu’il existe.
  3. Vérifier le message de confirmation ou l’état de synchronisation.
  4. Pour une modification importante, produire l’export adapté : JSON pour sauvegarde, CSV pour exploitation tabulaire, PDF pour archivage/revue.
  5. Avant toute restauration/import, créer une sauvegarde de l’état actuel.
FormatUsage recommandé
JSONSauvegarde et restauration de données structurées.
CSVAnalyse Excel, suivi de registre, extraction de tableaux.
PDF / impressionÉtat figé pour revue, diffusion, signature ou archivage.
HTMLDans les Appendices OMM, sauvegarde d’une copie autonome du document mis à jour.
Attention : Une restauration peut écraser l’état courant. Vérifier le fichier, son origine, sa date et le module concerné avant confirmation.

4. Flux de travail transversal recommandé

Les modules doivent être utilisés comme les composantes d’un même système de management. Un évènement ou une constatation ne doit pas rester isolé dans un seul registre lorsque d’autres modules sont concernés.

  1. Détecter / signaler : rapport mobile, occurrence, résultat d’audit, signal CAMO, contrôle interne ou information externe.
  2. Qualifier : catégoriser l’évènement et identifier le risque, la famille de risque ou l’exigence concernée.
  3. Évaluer : déterminer le niveau de risque ou la gravité de la non-conformité selon l’outil utilisé.
  4. Traiter : définir barrières, actions correctives, responsables, échéances et preuves.
  5. Vérifier l’efficacité : ne pas fermer une action uniquement parce qu’elle est réalisée ; vérifier le résultat attendu.
  6. Réexaminer : utiliser SPI/KPI, Safety Assurance, SRB, audits et rapport annuel pour détecter les tendances et décider des actions de management.
À retenir : Utiliser systématiquement les références croisées disponibles : ID de risque, occurrence, étude de changement, constatation, action, document ou audit.

5. Safety / Security Report — utilisation détaillée

Le formulaire mobile permet de choisir entre SAFETY et SECURITY. Les champs affichés changent selon le type sélectionné. Le formulaire permet aussi le signalement anonyme.

5.1 Créer un signalement

  1. Choisir SAFETY pour un évènement de sécurité des vols ou SECURITY pour un évènement de sûreté / Part-IS.
  2. Activer Anonymat si aucune donnée d’identité ne doit être transmise.
  3. Sélectionner l’entité concernée.
  4. Choisir le ou les types d’évènement proposés.
  5. Compléter les informations opérationnelles affichées : aéronef, immatriculation, équipage, date, heure locale, lieu, base, phase de vol, etc.
  6. Lorsque la maintenance est concernée, compléter les informations Part-145/CAMO affichées.
  7. Sélectionner la conséquence de l’évènement et renseigner toute pression ressentie si applicable.
  8. Décrire les faits dans l’ordre chronologique, en séparant les observations des suppositions.
  9. Renseigner les mesures prises immédiatement et les commentaires/suggestions utiles.
  10. Sélectionner Envoyer / Submit puis attendre la confirmation et la référence générée.

5.2 Cas Security / Part-IS

  • Si l’évènement est en cours (intrusion, menace, colis suspect, cyberattaque active), appliquer d’abord les moyens d’alerte opérationnels prévus.
  • Ne pas détailler inutilement une vulnérabilité exploitable dans une zone diffusée largement.
  • Le formulaire accepte le mode anonyme, mais cela peut limiter les possibilités de suivi.

5.3 Fonctionnement hors ligne / erreur réseau

Si l’écriture vers le backend échoue, la version fournie tente de conserver localement le rapport sur l’appareil. Le message d’erreur indique alors si le rapport a été conservé et affiche sa référence. Rouvrir la même page lorsque le réseau est rétabli afin de transmettre les éléments en attente.

Attention : Dans la version analysée, les fichiers sélectionnés par le formulaire sont listés dans l’interface et leur nombre est enregistré, mais le code fourni ne montre pas de transfert effectif des fichiers vers un stockage distant. Ne considérer donc pas une pièce jointe comme archivée tant que son stockage n’a pas été vérifié.

6. SMS — orientation générale

Le SMS est organisé autour d’un tableau de bord et de registres spécialisés. La navigation principale donne accès au Risk Register, Management of Change, ERP, SPI, Occurrence Log et Event Accounting, ainsi qu’aux outils de politique, barrières, Bow-Tie, lessons learned, formation, assurance, audits internes, ALoS/Safety Case et interface CAMO→SMS.

6.1 Tableau de bord SMS

Le Dashboard est le point de lecture rapide. Il doit être utilisé pour identifier les éléments nécessitant une action avant d’entrer dans les registres détaillés.

  1. Ouvrir Dashboard.
  2. Examiner les compteurs, indicateurs et éléments en attente.
  3. Repérer les risques élevés, actions ouvertes, occurrences récentes ou signaux nécessitant une revue.
  4. Cliquer ensuite sur le module détaillé concerné pour documenter l’analyse ou la décision.
À retenir : Le tableau de bord sert à orienter la revue ; la donnée de référence reste le registre détaillé correspondant.

6.2 APP08-OMM — Risk Register

Le Risk Register centralise les scénarios de risque. Il permet la recherche, le filtrage, l’affichage dense, la modification, la copie, l’ajout et l’export. Les lignes comprennent notamment la famille, l’évènement/scénario, les évaluations initiales et résiduelles, les barrières et les informations de suivi.

Créer ou mettre à jour un risque

  1. Ouvrir APP08-OMM — Risk Register.
  2. Utiliser la recherche ou les filtres pour vérifier si le scénario existe déjà.
  3. Si nécessaire, choisir ADD NEW EVENT ou la fonction d’édition d’une ligne existante.
  4. Renseigner un scénario atomique : un danger/évènement clairement défini, sans mélanger plusieurs scénarios indépendants.
  5. Évaluer le risque initial selon la matrice utilisée par SAF.
  6. Décrire les barrières/mesures de maîtrise et leur état.
  7. Évaluer le risque résiduel après mesures.
  8. Attribuer propriétaire, suivi, preuves et date de révision si ces champs sont proposés.
  9. Enregistrer les modifications.

Filtres et exports

  • La barre de recherche et les filtres permettent d’isoler une famille, un niveau ou un sous-ensemble de risques.
  • CSV convient à l’analyse tabulaire et au contrôle de cohérence.
  • PDF convient à une revue ou à un état de référence.
  • Le module comporte aussi des exports vers le CMS pour assurer la liaison entre sécurité et conformité.
Attention : Éviter de créer un doublon lorsque le scénario existe déjà. Mettre à jour le risque existant lorsque l’exposition ou les barrières changent.

6.3 APP09-OMM — Management of Change

Le module Management of Change sert à analyser un changement organisationnel, opérationnel, technique ou réglementaire avant ou pendant sa mise en œuvre.

  1. Sélectionner Management of Change.
  2. Créer une New Change Study.
  3. Décrire le changement, son origine, le périmètre, les responsables et les échéances.
  4. Identifier les dangers, risques, interfaces et impacts réglementaires associés.
  5. Importer ou rattacher des risques existants lorsque l’interface le permet.
  6. Définir les actions, mesures de maîtrise, critères d’acceptation et preuves attendues.
  7. Enregistrer l’étude et ses versions successives.
  8. Mettre à jour la revue au fur et à mesure du déploiement.
  9. Ne clôturer le changement qu’après vérification de l’efficacité des mesures et traitement des actions ouvertes.
À retenir : Utiliser la version PDF de l’étude lorsqu’un état figé doit être présenté en revue ou archivé.

6.4 APP10-OMM — Emergency Response Plan

Le module ERP regroupe les informations de réponse d’urgence accessibles depuis le SMS et propose une fonction d’impression.

  1. Ouvrir Emergency Response Plan.
  2. Vérifier les contacts, responsabilités, numéros et informations opérationnelles avant diffusion.
  3. Mettre à jour les entrées autorisées lorsqu’un changement d’organisation ou de contact intervient.
  4. Utiliser Print ERP pour produire une copie utilisable hors connexion si nécessaire.
  5. Après un exercice ou un évènement réel, enregistrer les enseignements dans les modules appropriés : lessons learned, assurance, actions ou MoC.
Attention : Une copie imprimée peut devenir obsolète. Vérifier systématiquement version et date avant utilisation.

6.5 APP11-OMM — Safety Performance Indicators

Les SPI permettent de suivre les objectifs de performance sécurité. Le module contient des cibles, des valeurs et des représentations permettant de visualiser la tendance.

  1. Ouvrir Safety Performance Indicators.
  2. Contrôler la période de référence et les heures/volumes utilisés pour les indicateurs normalisés.
  3. Mettre à jour les valeurs sources lorsque nécessaire.
  4. Vérifier les cibles et seuils applicables.
  5. Analyser la tendance plutôt qu’une seule valeur ponctuelle.
  6. Documenter les décisions lorsqu’un seuil est atteint ou qu’une évolution défavorable apparaît.
  7. Utiliser les résultats lors de la SRB et de la Safety Assurance.
À retenir : Un indicateur n’est utile que si sa source, sa formule, sa fréquence et sa réaction attendue sont connues.

6.6 APP12-OMM — Occurrence Log

L’Occurrence Log reçoit et suit les évènements. Il offre la création d’occurrence, l’impression, l’ajout d’actions correctives et les champs nécessaires à l’analyse.

  1. Ouvrir Occurrence Log.
  2. Rechercher d’abord la référence du rapport reçu afin d’éviter un doublon.
  3. Créer une New Occurrence si l’évènement n’existe pas.
  4. Compléter les faits, la date, l’aéronef/opération et la source.
  5. Classer l’évènement dans la taxonomie applicable et relier le scénario de risque lorsqu’il est identifié.
  6. Réaliser l’analyse prévue par le système : classification, facteurs contributifs, Just Culture, 5 Whys ou autres champs disponibles selon le cas.
  7. Créer les actions correctives avec responsable, échéance et statut.
  8. Suivre les actions jusqu’à leur vérification d’efficacité.
  9. Mettre à jour le statut de l’occurrence uniquement lorsque le traitement est réellement achevé.

Bon niveau de description

  • Faits observés : ce qui s’est produit.
  • Contexte : conditions opérationnelles utiles.
  • Conséquences réelles et potentielles.
  • Mesures immédiates.
  • Analyse causale séparée des faits.
  • Actions et preuves de clôture.

6.7 APP13-OMM — Event Taxonomy & Accounting

Event Accounting structure la taxonomie des évènements et permet de compter les occurrences selon des catégories cohérentes. Il sert notamment à vérifier les tendances et la couverture du registre de risques.

  1. Ouvrir Event Accounting.
  2. Vérifier les catégories et familles auxquelles les évènements sont associés.
  3. Examiner les volumes et tendances affichés.
  4. Utiliser NEW EVENT CANDIDATE lorsqu’un évènement récurrent ou significatif n’est pas correctement représenté dans le registre de risques.
  5. Exporter en CSV pour analyse complémentaire si nécessaire.
  6. Faire valider toute création ou reclassification de risque selon le processus SMS interne.
À retenir : Event Accounting sert à détecter les écarts entre les évènements réellement observés et les scénarios déjà suivis dans le Risk Register.

6.8 Safety Policy, Controls Review et barrières

Ces outils permettent de passer de la politique générale à la vérification concrète des moyens de maîtrise.

Safety Policy & Objectives

  • Consulter la politique et les objectifs définis.
  • Vérifier que les objectifs restent cohérents avec les SPI et les décisions de management.
  • Toute modification de politique doit suivre le processus de gouvernance documentaire applicable.

Controls Review

  • Examiner périodiquement les contrôles/mesures de maîtrise.
  • Documenter leur état, leur pertinence et les éléments de preuve disponibles.
  • Créer une action ou une étude de changement si un contrôle devient insuffisant.

Registre des barrières

  • Maintenir une définition claire de chaque barrière.
  • Éviter les doublons de barrières portant des noms différents.
  • Relier les barrières aux scénarios de risque concernés.

Efficacité des barrières

  • Évaluer l’efficacité sur la base d’éléments objectifs.
  • Conserver les preuves de test, d’exercice, d’audit ou de retour d’expérience.
  • Réviser le risque résiduel lorsque l’efficacité réelle diffère de l’hypothèse initiale.

6.9 Bow-Tie Analysis

Le Bow-Tie visualise les menaces conduisant à un évènement redouté, les barrières préventives, les conséquences et les barrières de récupération/atténuation.

  1. Sélectionner le risque ou scénario à étudier.
  2. Définir l’évènement central de manière unique et concise.
  3. Lister les menaces à gauche.
  4. Associer les barrières préventives réellement existantes.
  5. Lister les conséquences à droite.
  6. Associer les barrières d’atténuation/récupération.
  7. Vérifier la cohérence avec le registre des barrières et le Risk Register.
  8. Exporter/imprimer la structure Bow-Tie lorsque nécessaire.
Attention : Ne pas utiliser le Bow-Tie comme simple dessin. Chaque barrière affichée doit correspondre à un contrôle identifiable et vérifiable.

6.10 Lessons Learned et Safety Promotion

Le module Lessons Learned / Safety Alert & Communications permet d’enregistrer les enseignements et supports de communication sécurité.

  1. Créer une nouvelle leçon lorsqu’un évènement, audit, exercice ou tendance justifie une communication.
  2. Décrire le message clé et la population concernée.
  3. Éviter d’inclure des données personnelles ou confidentielles non nécessaires.
  4. Définir le canal de diffusion et, si applicable, la date.
  5. Conserver une preuve de diffusion ou de briefing.
  6. Réévaluer ultérieurement si le message a produit l’effet attendu.

6.11 SMS Training & Competence Records

Le registre de formation SMS permet de conserver les formations et compétences associées aux personnes concernées.

  1. Ouvrir SMS Training & Competence Records.
  2. Créer New training record.
  3. Sélectionner la personne, le type de formation, la date et les informations de validité disponibles.
  4. Ajouter les éléments de preuve ou références demandés par l’interface.
  5. Contrôler les échéances et renouvellements.
  6. Utiliser les données lors des revues de compétence et audits.
À retenir : Une entrée de formation doit permettre de démontrer qui a été formé, à quoi, quand, selon quel standard et avec quelle preuve.

6.12 Safety Assurance — Effectiveness Review

Safety Assurance sert à vérifier que les contrôles, actions et changements produisent réellement l’effet recherché.

  1. Créer une New Review.
  2. Identifier l’objet de la revue : risque, action, changement, barrière, processus ou indicateur.
  3. Définir la preuve attendue et la période d’observation.
  4. Analyser les données disponibles.
  5. Conclure sur l’efficacité, l’efficacité partielle ou l’insuffisance.
  6. Créer une action complémentaire ou rouvrir l’analyse si nécessaire.
  7. Conserver la date, le responsable et la justification de la conclusion.

6.13 Audits internes SMS

Le module d’audits internes SMS complète le CMS lorsqu’une vérification porte spécifiquement sur l’efficacité du système de gestion de la sécurité.

  1. Créer un Nouvel audit.
  2. Définir périmètre, critères, auditeur et date.
  3. Rassembler les preuves avant de conclure.
  4. Enregistrer les écarts/observations et les actions associées.
  5. Attribuer un responsable et une échéance.
  6. Vérifier la clôture et l’efficacité des actions.
  7. Utiliser les tendances en Safety Assurance et en SRB.

6.14 ALoS / Safety Case

Le module ALoS / Safety Case permet de documenter une démonstration interne de performance ou d’acceptabilité sécurité pour un sujet donné.

  1. Créer un New Safety Case.
  2. Définir clairement le sujet et la décision à soutenir.
  3. Rassembler les hypothèses, données, risques et barrières pertinentes.
  4. Relier les éléments de preuve aux conclusions.
  5. Définir les critères de succès et les limites de validité.
  6. Réviser le Safety Case lorsqu’une hypothèse, une donnée ou une condition opérationnelle change.

6.15 Interface CAMO → SMS

L’interface CAMO→SMS est destinée à capter les signaux de navigabilité continue pouvant avoir une importance sécurité.

  1. Ouvrir CAMO → SMS Interface.
  2. Créer un Nouveau signal CAMO lorsqu’une information de maintenance/navigabilité justifie un suivi SMS.
  3. Décrire le signal et sa source.
  4. Évaluer s’il existe déjà un risque associé.
  5. Relier ou créer le scénario de risque nécessaire selon le processus SMS.
  6. Attribuer le suivi et la décision.
  7. Clôturer uniquement après traitement et vérification.

6.16 Export, import et sauvegarde SMS

Le module Export · Import · Backup regroupe plusieurs exports : registre des risques, occurrences, études de changement et sauvegarde complète. Il permet aussi l’import/restauration JSON.

  1. Pour une sauvegarde complète, utiliser Export all data (.json) ou l’export global approprié.
  2. Pour un besoin analytique, préférer les exports CSV ciblés.
  3. Pour une preuve documentaire, utiliser les exports PDF des registres concernés.
  4. Avant Import / Restore JSON, créer une sauvegarde fraîche.
  5. Vérifier l’environnement et le contenu du fichier importé avant confirmation.
  6. Après restauration, ouvrir plusieurs vues critiques pour vérifier la cohérence des données.
Attention : Une sauvegarde JSON peut contenir une grande partie de l’état du module. La conserver comme un document contrôlé et éviter les copies non maîtrisées.

7.1 Tableau de bord CMS et indicateurs

Le CMS contient un tableau de bord principal ainsi qu’un tableau de bord d’indicateurs EASA. Ils servent à identifier les audits à venir, constatations ouvertes, échéances et tendances.

  1. Ouvrir le tableau de bord.
  2. Vérifier les cartes KPI, statuts et alertes.
  3. Identifier les actions échues ou proches de l’échéance.
  4. Contrôler les répétitions de constatations ou tendances défavorables.
  5. Accéder au registre ou audit source avant de prendre une décision de clôture.

7.2 APP13-OMM — Plan d’audit

Le Plan d’audit permet d’organiser les audits sur la période de surveillance.

  1. Ouvrir APP13-OMM Plan d’audit.
  2. Contrôler le domaine, la référence, l’objectif, le mois/date et la priorité.
  3. Mettre à jour la planification si un changement justifié intervient.
  4. Conserver la traçabilité de la réalisation et des reports.
  5. Exporter le plan en CSV ou PDF lorsqu’un état de référence est nécessaire.
À retenir : Un report d’audit doit rester explicable et ne doit pas créer de lacune de couverture du programme.

7.3 APP14-OMM — Indicateurs de conformité

Les indicateurs CMS mesurent la performance du programme d’audit et du traitement des constatations.

  1. Vérifier la période des données.
  2. Mettre à jour les valeurs nécessaires.
  3. Contrôler les objectifs/seuils.
  4. Analyser les indicateurs en tendance.
  5. Documenter la réaction lorsque la performance franchit un seuil.
  6. Utiliser l’export PDF/CSV pour les revues de management.

7.4 APP15-OMM — Plan d’actions correctives (CAP)

Le CAP centralise les constatations et leurs actions correctives. Il est l’outil principal de suivi jusqu’à clôture.

  1. Créer ou importer la constatation avec sa référence.
  2. Décrire précisément l’écart et le critère applicable.
  3. Effectuer l’analyse de cause lorsque requise.
  4. Définir l’action corrective, le responsable et l’échéance.
  5. Ajouter les preuves de réalisation.
  6. Vérifier l’efficacité de l’action avant clôture.
  7. Mettre à jour le statut et conserver la justification.
Attention : Une action « réalisée » n’est pas nécessairement « efficace ». La clôture doit s’appuyer sur une vérification adaptée au risque et à la constatation.

7.5 APP16 à APP18 — Sous-traitants, auditeurs et formateurs

APP16 — Sous-traitants

  • Ajouter un sous-traitant avec l’identification et le domaine pertinent.
  • Maintenir les informations de surveillance/évaluation demandées.
  • Suivre les échéances et actions associées.

APP17 — Auditeurs et inspecteurs

  • Maintenir la liste des personnes habilitées.
  • Documenter compétences, qualifications ou périmètre selon les champs disponibles.
  • Vérifier l’indépendance et l’adéquation au domaine audité.

APP18 — Formateurs

  • Maintenir la liste des formateurs reconnus.
  • Conserver les informations de compétence et de domaine.
  • Mettre à jour le registre lorsqu’une habilitation évolue.
À retenir : Les trois registres disposent de fonctions d’ajout, d’export CSV et d’impression.

7.6 SRB Checklist et revue SRB

Le CMS propose deux outils complémentaires : une checklist structurée de préparation et une fiche de revue SRB avec participants, constatations, actions, décisions et signatures.

  1. Préparer la réunion avec SRB Checklist.
  2. Cocher les éléments réellement revus, sans utiliser la checklist comme simple formalité.
  3. Créer/ouvrir la revue SRB.
  4. Renseigner date, période, participants et invités.
  5. Examiner sécurité, conformité, actions, ressources, changements et tendances selon les rubriques disponibles.
  6. Ajouter les constatations/actions/décisions.
  7. Attribuer un responsable et une échéance.
  8. Signer ou valider selon le processus interne.
  9. Exporter la revue en PDF et conserver la version de référence.

7.7 Grille d’audit EASA

La grille EASA permet de sélectionner des exigences et de documenter le résultat de l’audit.

  1. Ouvrir Grille d’audit EASA.
  2. Choisir le domaine réglementaire ou utiliser la recherche.
  3. Ajouter les exigences nécessaires à la sélection.
  4. Lire l’IR et les AMC associés présentés par l’outil.
  5. Documenter les preuves, commentaires et résultats.
  6. Enregistrer la grille en JSON si elle doit être reprise ultérieurement.
  7. Exporter en PDF pour l’archivage de l’audit.
Attention : La grille facilite le travail mais ne dispense pas de vérifier que la version réglementaire chargée dans le système correspond à la version applicable à la date de l’audit.

7.8 Matrice de conformité

La matrice de conformité sert à relier exigences, documents/procédures internes, statut de conformité et preuves.

  1. Rechercher l’exigence ou le domaine concerné.
  2. Renseigner la référence documentaire interne.
  3. Déterminer le statut sur la base d’une preuve vérifiable.
  4. Ajouter commentaire ou action lorsque la conformité est partielle ou absente.
  5. Mettre à jour la matrice après modification documentaire ou réglementaire.

7.9 Veille réglementaire

La veille réglementaire permet d’enregistrer une source, sa date, le sujet et le statut d’analyse.

  1. Ajouter ou consulter une entrée de veille.
  2. Vérifier la source officielle lorsqu’un lien est disponible.
  3. Déterminer l’applicabilité au périmètre SAF.
  4. Documenter l’analyse et les actions nécessaires.
  5. Marquer l’élément comme analysé uniquement lorsque la conclusion est tracée.
  6. Créer un MoC, CAP ou changement documentaire si l’évolution a un impact.

7.10 Sécurité (SMS) — passerelle de lecture

L’onglet Sécurité (SMS) présente des données issues du SMS en lecture seule afin de permettre au Compliance Monitoring de prendre en compte les informations sécurité sans dupliquer leur gestion.

  1. Ouvrir Sécurité (SMS).
  2. Consulter les éléments chargés depuis le SMS.
  3. Utiliser ces données pour préparer un audit, une SRB ou une analyse de conformité.
  4. Effectuer toute modification dans le module SMS d’origine, pas dans la passerelle de lecture.

7.11 Audits & Authority

Ce module regroupe le suivi d’audits, ordres de mission, contacts/notifications et éléments liés aux relations avec l’autorité selon les sous-sections proposées.

  1. Créer l’entrée d’audit ou ordre de mission.
  2. Renseigner le périmètre, les dates et les responsables.
  3. Enregistrer les contacts/notifications utiles.
  4. Relier les constatations et CAP correspondants.
  5. Conserver les documents et preuves selon les fonctions disponibles.
  6. Mettre à jour le statut jusqu’à clôture formelle.

7.12 Rapport annuel et paramètres CMS

Le rapport annuel consolide les données de conformité pour la période. Les paramètres regroupent les réglages nécessaires au fonctionnement du module.

Rapport annuel

  • Vérifier que le plan d’audit, les constatations, CAP et KPI sont à jour avant génération.
  • Contrôler les totaux et tendances.
  • Ajouter les commentaires de management nécessaires.
  • Imprimer/exporter le rapport et conserver la version approuvée.

Paramètres

  • Modifier uniquement les paramètres compris et autorisés.
  • Éviter les changements de configuration pendant une opération de sauvegarde/import.
  • Après modification, tester les vues principales du CMS.

8.1 APP01-OMM — Liste des appendices

APP01 sert d’index documentaire. Les cellules éditables permettent de maintenir références, titres, versions et dates ; des sélecteurs peuvent associer les fichiers disponibles.

  1. Vérifier le document à mettre à jour.
  2. Modifier uniquement les cellules nécessaires.
  3. Contrôler version et date après saisie.
  4. Ajouter une ligne uniquement lorsqu’un document doit réellement être référencé.
  5. Utiliser l’export PDF pour produire un état figé.
  6. Utiliser Save HTML si une nouvelle copie autonome du module doit être conservée.

8.2 APP02-OMM — Facilities & Infrastructure

Cet appendice décrit les installations et infrastructures. Utiliser les zones éditables pour maintenir les informations pertinentes et les photographies/plans lorsqu’ils sont intégrés.

  1. Contrôler que la base ou installation concernée est correctement identifiée.
  2. Mettre à jour les données factuelles uniquement.
  3. Vérifier la cohérence des plans/photos après modification.
  4. Exporter en PDF pour revue ou dossier documentaire.

8.3 APP03-OMM — Organigramme

L’organigramme matérialise les relations fonctionnelles et de reporting. La légende différencie les types de liens utilisés.

  1. Vérifier les titulaires et fonctions.
  2. Mettre à jour l’organigramme uniquement après validation du changement organisationnel.
  3. Contrôler que les lignes de reporting/fonction restent cohérentes.
  4. Exporter en PDF après modification.
À retenir : Un changement d’organisation significatif doit être traité dans le Management of Change avant de n’être qu’un simple changement graphique.

8.4 APP04-OMM — Personnel de management

APP04 maintient la liste du personnel de management et les informations associées.

  1. Mettre à jour la fonction, le titulaire et les informations pertinentes.
  2. Supprimer une ligne uniquement si la fonction/personne n’est plus applicable et si la traçabilité documentaire est assurée ailleurs.
  3. Vérifier la cohérence avec l’organigramme APP03.
  4. Exporter en PDF après validation.

8.5 APP05-OMM — Leasing Overview by FOCA

Cet appendice présente les informations de leasing suivies dans le système.

  1. Vérifier l’aéronef et le type d’accord concerné.
  2. Mettre à jour les périodes et références.
  3. Contrôler la cohérence avec les autorisations/documentation de l’opérateur.
  4. Exporter en PDF lorsque nécessaire.

8.6 APP06-OMM — Aircraft being used

APP06 recense les aéronefs utilisés avec les informations principales nécessaires à l’appendice.

  1. Identifier précisément l’aéronef.
  2. Mettre à jour immatriculation, type et autres champs applicables.
  3. Contrôler la cohérence avec les autres bases et documents de flotte.
  4. Exporter l’appendice après modification.

8.7 APP07-OMM — Safety Promotion

APP07 gère les éléments de promotion sécurité et comporte des fonctions d’ajout de campagnes ainsi que d’impression/sauvegarde PDF.

  1. Créer une campagne ou activité de promotion lorsqu’elle est décidée.
  2. Renseigner le sujet, la population et la période.
  3. Conserver les preuves de diffusion/participation lorsque nécessaire.
  4. Mettre à jour l’état ou le résultat après réalisation.
  5. Imprimer/enregistrer en PDF pour archivage.

8.8 Sauvegarder les Appendices OMM

Le bouton Save (HTML) produit une copie HTML autonome intégrant les modifications présentes dans la page. Il s’agit d’une sauvegarde de fichier, différente d’une simple impression PDF.

  1. Effectuer les modifications nécessaires.
  2. Vérifier visuellement toutes les vues concernées.
  3. Utiliser Save (HTML).
  4. Conserver le fichier sous un nom/version permettant d’identifier l’état documentaire.
  5. Rouvrir le fichier sauvegardé pour vérifier que les modifications sont bien présentes.
  6. Utiliser le PDF pour un état figé destiné à la consultation ou à l’archivage.

9. Dépannage et contrôles de premier niveau

SymptômeContrôles à effectuer
Module inaccessible depuis HOMEVérifier le rôle affiché, la session, puis le chemin du fichier déployé.
Champ non modifiableVérifier si le profil est Reader/Authority ou si la vue est volontairement en lecture seule.
Donnée non enregistréeVérifier que le bouton Save a été utilisé et qu’aucun message d’erreur n’est affiché.
Import refuséVérifier type de fichier, module d’origine, structure JSON et droits de l’utilisateur.
PDF incompletRéessayer depuis la vue à exporter et contrôler les paramètres d’impression du navigateur.
Donnée absente après restaurationOuvrir le registre source, contrôler la sauvegarde importée et comparer avec un export antérieur.
Rapport mobile non envoyéConserver la référence affichée, vérifier le réseau puis rouvrir le formulaire pour permettre la reprise des rapports en attente.
Pièce jointe du rapport introuvableDans cette version, vérifier séparément le stockage effectif des fichiers ; la sélection locale n’est pas une preuve d’archivage.

Avant toute investigation technique

  1. Noter le module, la vue, l’action réalisée et le message exact.
  2. Ne pas lancer plusieurs imports/restaurations successifs pour « tester ».
  3. Créer un export de sauvegarde si l’état actuel est encore accessible.
  4. Reproduire le problème avec un jeu de données non critique lorsque possible.

10. Routine d’utilisation recommandée

Quotidien / au fil des évènements

  • Traiter les nouveaux signalements et occurrences.
  • Mettre à jour les actions arrivant à échéance.
  • Créer un MoC avant un changement significatif plutôt qu’après sa mise en œuvre.

Hebdomadaire / périodique selon activité

  • Revoir les risques élevés et les barrières critiques.
  • Contrôler les données SPI et les tendances.
  • Vérifier les CAP et constats ouverts.
  • Contrôler les signaux CAMO et les interfaces sécurité/conformité.

Avant SRB / revue management

  • Mettre à jour Dashboard, SPI/KPI, Risk Register, Occurrence Log et CAP.
  • Préparer la SRB Checklist.
  • Identifier les décisions attendues et actions en retard.
  • Vérifier les changements ouverts et l’efficacité des mesures.

Après toute modification majeure

  • Enregistrer.
  • Vérifier.
  • Exporter une preuve adaptée.
  • S’assurer que la modification est reflétée dans les modules liés.
